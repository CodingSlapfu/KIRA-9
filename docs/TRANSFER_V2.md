# KIRA-9 transfer protocol v2
Standard FM-1 SysEx framing (00 59 command length24 payload complemented-byte-sum, bitstream packed to seven bits) remains interoperable with the updater. Commands 62 BEGIN, 63 WRITE, 64 COMMIT, 65 READ, 66 ABORT respond on 67. Transaction identifiers are 16-bit. Maximum object 3840 bytes; chunks 96 bytes; staging expires after five seconds of inactivity. No flash write occurs before full length, file CRC and content validation. Duplicate WRITE is checked against staged bytes; duplicate COMMIT returns the cached result without flash wear. READ returns total length and whole-file CRC per chunk. All storage/network work runs on the main loop; the audio interrupt never waits for a transfer.

Kinds 0 song, 1 phrase, 2 word each have eight slots. Kinds 3 pronunciation and 4 voice bank use slot zero. K9S1 remains readable. K9S2 delta-encodes the same events in eight bytes and retains UTF-8 editable project metadata. K9D1 records store the editable pronunciation dictionary. K9V2 has eight bounded compiled parameter records plus editable JSON names. All are versioned and CRC protected.

The current browser uses one transfer per output port, bounded retries and idempotent commit. Corrupt/out-of-order responses cannot be applied. New transactions recover from disconnect; an aborted or expired upload leaves the last committed object intact. The pipe fixture tests the actual C transfer/codec/library modules from JavaScript MIDI framing, not a second device algorithm.
